# Audit of Walder — final report (2026-11-13/14)

Branch `audit-2026-11` off `0a12a61`. Everything is uncommitted in the working tree. Scope, in the
owner's words: backend, frontend, security and every screen on macOS ("iOS" was read as macOS) and
Windows. No Windows machine was reachable from the Mac, so Windows was covered by reading the code
and a cross-build only.

**Outcome.** 78 findings survived independent verification: 57 confirmed, 11 plausible, 6 refuted,
4 by design. By severity: 2 high, 15 medium, 61 low. Of the 78: **60 fixed**, **3 skipped because
they need a Windows machine**, **3 turned into QA-checklist notes only**, **7 left as the owner's
call**, **5 not defects** (60 + 3 + 3 + 7 + 5 = 78).
Five reviewers then found 16 issues in the first fixes (R1–R16, all fixed), a re-review of those
fixes found 10 more low ones (all fixed in round 3), and a last review of round 3 found two more
low ones (fixed). Gate on the Mac, 2026-11-14 04:34, on the final tree, each judged by exit code:
`npm run typecheck` 0; `npm test` 0 (80 files, 2728 passed, 2 skipped); `npm run build` 0. **The Windows half is open:** nothing has run on Windows yet.

Method: 9 parallel read-only auditors plus an on-screen pass of every Mac screen (evidence in
`~/Walder-qa/2026-11-13-audit/`), one independent skeptic per finding, fix owners with disjoint
files, then fresh reviewers, twice. One honesty note on the gate: during round 2 the suite showed
5 s timeouts on random synchronous tests (a different test each run, no assertion failed) while
the Mac was on battery and cycling through maintenance sleep. The final run, under `caffeinate`,
was clean.

## Release notes need

- **S1 caveat.** The POSIX hook command now carries `--noproxy 127.0.0.1`. Existing installs keep
  the old command until **Install … hooks…** is chosen again, and Codex then asks for `/hooks`
  trust again.
- Windows first-run hello: "Hello. Click the bone in your tray." (macOS keeps "menu bar").
- After **Report a bug…** the dog says "Diagnostics copied to clipboard".
- A `?` is per session: another session of the same tool no longer clears it, and two blocked
  sessions each keep their `?`. A `?` is dropped 30 minutes after it was queued, on screen or not.
- macOS: a quick second click on the bone opens a menu with fresh countdowns.
- A crashed overlay renderer reloads itself (at most three times per run) instead of leaving the
  dog gone until Restart.
- Hide when idle no longer hides him while the cursor rests on him.
- Logging in through Accounts no longer spends the 60 s Refresh cooldown.
- ChatGPT: a 429 now backs off with Retry-After instead of reading as "endpoint changed".
- Cursor, Copilot and Gemini rows survive a restart (they were dropped on restore).
- A settings file starting with a byte-order mark no longer resets every setting.
- Launch at login: an entry waiting for approval on macOS shows ticked and can be unticked. On
  Windows the uninstaller removes the startup entry (not on an update; untested).
- Windows: token renewal looks only for `claude.exe` (an npm-only install reads "no claude binary
  found"); the Copilot `gh` read no longer flashes a console window.
- Docs: macOS 13 is the minimum; Gemini is macOS-only for now.

When CI runs what (`.github/workflows/ci.yml`):

- The **check** job (ubuntu: typecheck + `npm test`) runs on every pull request, on a push to
  `main`, on a `v*` tag and on a manual run. Pushing `audit-2026-11` by itself triggers nothing;
  opening a pull request runs the check job only.
- The **Windows** job runs only on a manual run (`workflow_dispatch`) or a `v*` tag. Its new
  `npm test` step is the last one, after `npm ci`, `npm run dist:win`, the installer upload and
  the SmartScreen note, so it runs only if the installer build succeeded. The live
  `fullscreen-win-helper` test needs a foreground window; whether a hosted runner has one is
  unknown until the first run.

To run the Windows job on the branch without a tag:
