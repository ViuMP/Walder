# Walder 0.2.3

A packaging fix and nothing else — no behaviour in the app changed. It is the release that
makes Walder installable without a terminal.

## Fixed
- **macOS no longer says Walder is "damaged".** Every release up to and including 0.2.2 shipped a bundle whose code signature did not verify, and macOS reports a downloaded app in that state as *damaged* rather than as merely untrusted — a dialog with **no Open Anyway button** and no way past it except a Terminal command. The bundle is now signed properly, so the block you get on first launch is the ordinary "unidentified developer" one, and **System Settings ▸ Privacy & Security ▸ Open Anyway** is enough. The four steps in the README are now the whole install.

  Nothing about *trust* changed: Walder still has no Apple developer certificate and is still not notarised, so macOS still refuses to open it until you say so. What changed is that it now refuses in a way you can answer.

## Notes
- **Apple Silicon only**, as before. This build is `arm64`; there is no Intel (`x64`) build, and on an Intel Mac it will not open at all.
- **If you are on 0.2.2 or older and stuck on the "damaged" dialog**, installing this release is the fix — you do not need to run `xattr` first. The old workaround still works if you would rather keep the build you have.
- The attached handbook is the 0.2 edition, unchanged since 0.2.2.
