# Walder 0.2.4

An internal correctness release. **Nothing you can see has changed** — no new features, no
behaviour fixed, nothing that was broken for you before. If you are on 0.2.3, there is nothing here
you need; install it whenever it happens to be convenient.

## Why it exists

Walder's code was given a full security review — the main process, the IPC bridge and preload, the
login window, the credential and network layer, the renderer, and the build and release scripts.
**It found no vulnerabilities.** Nothing was exposed, in this version or in any earlier one, and no
earlier release is unsafe to keep using.

What it did find was four things that were wrong on their own terms: two checks that did not cover
everything their own documentation said they covered, and two comments that described the code as
doing something it did not do. None of the four was reachable by an attacker. They are fixed here
because code that does not match its own stated intent is how a real bug gets in later, not because
anything was at risk now.

## Changed

- **The login window's "is this address this machine?" check now recognises two more ways of
  writing the same thing.** It already refused `127.0.0.1`, `::1` and `localhost`; it now also
  refuses the IPv4-mapped IPv6 form (`::ffff:127.0.0.1`, which the URL parser rewrites into hex
  before the check ever sees it) and names written with a trailing dot (`localhost.`). Both reach
  this machine, and both were previously allowed through that particular check.

  This was never a way into anything. The check governs where the login window may *navigate*, the
  only thing Walder itself listens for locally is plain `http` — which a separate, earlier rule
  already refuses outright — and that listener independently validates every request it receives.

- **A stored endpoint hint can no longer be written with a doubled leading slash.** Walder learns
  which ChatGPT address carries your quota by watching the site ask for it, and keeps the path. A
  path beginning `//` would have been read as a different host if it were ever replayed. It never
  was — the value was already being cleaned every time it was read back — but it is now refused when
  it is written, too, so both ends agree.

- **Two comments that overstated what the code does** are corrected: one named the wrong port
  number, and one claimed a guarantee the code does not provide.

## Notes

- **Apple Silicon only**, as before. This build is `arm64`; there is no Intel (`x64`) build.
- The first-launch steps are unchanged from 0.2.3 — macOS will still ask you to allow an app from an
  unidentified developer, and **System Settings ▸ Privacy & Security ▸ Open Anyway** is still the
  answer.
- The attached handbook is the 0.2 edition, unchanged since 0.2.2.
