# Walder 0.2.5

The release where the dog finds his voice again. Most of it comes from one afternoon of reports:
a bark that arrived cut off, a bark that repeated itself, a hover card that would not appear over a
full-screen app, an update check that said nothing, and a dog who had stopped reacting to Claude
Code altogether — which turned out to be hooks that were never installed and an app that had no
way to notice.

## Fixed

- **Bubbles are never cut off.** `7-day (all models): 80%…` is gone. The window is now widened for
  the whole sentence on one line, and the column estimate follows the real width of the system's
  monospace font. Every sentence Walder can say is checked against the renderer's own arithmetic at
  five pixel ratios.
- **A threshold barks once.** Restarting Walder no longer re-announces a level he already barked
  about, and a rolling window easing back from 84 % to 81 % no longer re-arms the 80 % bark. The
  bubble still prints the observed number — `81% used` when that is the reading.
- **The hover card comes back over a full-screen Space.** On macOS a window can be "visible" on
  another Space; the card was being re-placed there forever. It is now shown again on every hover,
  and a card whose renderer died is reloaded.

## New

- **He says which tool finished.** `Claude done` and `Claude waiting` replace `woof` and the bare
  `?`; Codex gets `Codex done` and `Codex waiting`. A Claude and a Codex reply seconds apart both
  show, and a new prompt clears only its own tool's wait. The pixel `?` still appears by his ear.
- **Codex hooks.** Install Codex hooks… writes three entries to `~/.codex/hooks.json` (`Stop`,
  `PermissionRequest`, `UserPromptSubmit`). Codex runs a new hook only after you trust it once —
  open a terminal, run `codex`, type `/hooks`, and trust Walder's entries. Codex has no event for
  plan-mode questions, so `Codex waiting` covers command and patch approvals only. Walder does not
  touch the `notify` setting.
- **Walder tells you when his hooks are missing.** The tray shows `Claude Code hooks: installed
  (port 47811)` or `not installed`, and the same for Codex. If they are missing at launch he says so
  once, and on a machine that has the tool he offers to install them — once, and never again if you
  decline.
- **"You're up to date."** A manual Check for updates now that finds nothing newer says so in a
  bubble. Scheduled checks stay silent.
- **Report a bug…** opens a prefilled GitHub issue on the releases repository with an environment
  block — version, macOS, Electron, displays, your settings, the update state, the log path. No
  account name and no usage number can be in it. Nothing is sent until you press Submit on GitHub;
  the block is also on your clipboard. Developer ▸ Reveal log file opens Finder on `walder.log` so
  you can attach it.
- **Show in overview.** A checkbox per row in the tray menu. A hidden row leaves the hover card at
  once and never barks; the face still follows the Claude 5-hour window.

## Notes

- **Apple Silicon only**, as before.
- The first-launch block is unchanged: **System Settings ▸ Privacy & Security ▸ Open Anyway**, and
  click **Done**, not "Move to Trash". The README has the four steps.
- If Walder has never reacted to Claude Code for you, this is why: Tray ▸ Install Claude Code
  hooks…, then restart Claude Code.
